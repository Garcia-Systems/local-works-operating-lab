# Change Classification Guide

Classification is evidence-led and “usually paid” is guidance, never an automatic invoice.

| Type | Definition | Typical example | Usually customer-paid? | Typical next step |
|---|---|---|---|---|
| CLARIFICATION | Non-material detail of approved behavior | Define approve/deny outcomes | GENERALLY NO | Confirm and record |
| DEFECT | Delivery fails an approved requirement or acceptance criterion | Eligible case follows the wrong route | GENERALLY NO | Correct and retest |
| DELIVERY_CORRECTION | Missing or incorrect agreed technical responsibility | Promised documentation missing | GENERALLY NO | Correct delivery |
| REQUIREMENT_CORRECTION | Prior business understanding proves wrong | Policy excludes a membership type | DEPENDS | Investigate causality and fairness |
| TECHNICAL_DISCOVERY | New capability evidence changes the approach | API lacks write access | DEPENDS | Revisit solution and estimate |
| DEPENDENCY_CHANGE | Controlled dependency changes | Vendor disables a capability | DEPENDS | Record controller, impact, options |
| CUSTOMER_ENHANCEMENT | Customer asks for added capability | Add reporting view | POSSIBLY | Compare scope and value |
| SCOPE_CHANGE | Workflow, actor, system, data, acceptance, timing, responsibility, or support boundary materially changes | Add excluded cancellation workflow | GENERALLY YES | Analyze and offer options |
| DEFERRED_IDEA | Useful idea intentionally outside active work | Phase 2 improvement | POSSIBLY | Preserve in backlog |
| UNKNOWN | Evidence cannot support a fair class yet | Unclear “we assumed” statement | DEPENDS | Clarify, investigate, review history |
